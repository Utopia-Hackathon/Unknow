
### 字段规则（缺一条即不合格）

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| `id` | ✅ | `s01` 起递增，**一经分配不复用**（删点位也不回收编号） |
| `name` | ✅ | **必须是真店名**，不得写「小吃茶饮区」这类区域名 |
| `floor` | ✅ | 只能是 `f6` / `f7` / `f8` |
| `category` | ✅ | 业态：火锅/湘菜/日料/自助/烤肉/饮品/融合菜… |
| `x` `z` | ✅ | 米。相对位置合理即可，不要求测量级精度 |
| `entrance` | ✅ | 门口落点，取店门中心外侧 1.5–2m。**点击跳转直接用它**（D007 要求） |
| `verified` | ✅ | **三级，见下**。这是治「推断当事实」的核心字段 |
| `source` | ✅ | RESEARCH 的 E 编号（如 `E26`）或 `现场 2026-11-29`。**填不出的点位不得入库** |
| `storefront` | ⬜ | 门头贴图路径。空则用纯色体块 + 文字招牌（D008 允许，验收不歧视） |
| `note` | ⬜ | 存疑说明，如「犇小喜 11-16 开业，门头可能仍在调整」 |

### `verified` 三级定义（不可混用）

| 值 | 含义 | UI 表现 | 能否写进「实采点位」统计 |
| --- | --- | --- | --- |
| `observed` | **现场拍到门头 + 确认位置** | 正常显示 | ✅ |
| `public` | 有公开来源确认**楼层**，位置未现场核 | 正常显示 | ❌（标注「楼层已核、位置示意」） |
| `unverified` | 楼层或存在性存疑 | **必须显示「示意位置，待现场核实」** | ❌ |

**硬规则：不得把 `public` 或 `unverified` 写成 `observed`。** 现有代码把太二写成 f7（实为 8F）、喜茶写成 f6（实为 1F）就是这个错。

### 数据完整性自检（B 交 PR 前跑）

```bash
# 缺字段、断楼层、重复 id、source 为空 —— 任一非空即不得提 PR
node -e "const d=require('./data/stores.json');
const e=d.stores.filter(s=>!['observed','public','unverified'].includes(s.verified)||!s.source||!s.entrance);
const ids=d.stores.map(s=>s.id); const dup=ids.filter((v,i)=>ids.indexOf(v)!==i);
console.log('bad:',e.length,'dup:',dup.length,'total:',d.stores.length);"
```

## 三、引擎接口（D 产 → C 消费）

文件：`src/engine/index.js`，**纯逻辑，不 import three.js**（这一条保证 D 能在 Node 里跑单测，不等 B 的素材）。

```js
export function createWorld(config) // config: { floors, stores, tables, seed }
// 返回 world，方法如下：

world.releaseTable(tableId)      // 释放空桌，触发匹配
world.tick(minutes)              // 推进模拟时间，返回本次产生的事件数组
world.getMetrics()               // 返回 { lossRate, avgWait, skippedCount, ... }
world.applyScenario(scenario)    // 假设推演：{ addTables, dropArrivalRate, ... } → 前后指标对比
```

**事件形状（D007 依赖，不可改）**：

```js
{ t: 12.5, type: 'skipped', personId: 'p17', tableId: 't3', reason: '桌型不匹配（需 2 人桌，空出 6 人桌）' }
```

| `type` | 含义 |
| --- | --- |
| `queued` | 取号入队 |
| `called` | 叫号 |
| `seated` | 落座 |
| `skipped` | 跳号（跳过排位靠前者） |
| `reflowed` | 过号后回捞 |
| `lost` | 顾客离开（计入流失） |

**`reason` 必填**——F02-01 验收要求「界面解释跳号原因」，没这个字段就无处取数，只能编。
