# 提交与协作手册

版本：v0.1
更新日期：2026-11-24
适用基准：开发书 v0.1、AGENTS.md v0.1、团队方案 v0.1

本文维护 Git 流程、独立环境与复核约定。
本文不维护：产品范围（开发书）、工程规则（AGENTS.md）、真实命令清单（RUNBOOK.md）。
下列命令为操作示例，不表示已经执行，也不替代编码助手所需的 Git 操作授权。

## 仓库组织

- 一个主仓库 + 一个主分支 + 按任务建的分支 + 通过 PR 合入。[待确认：按项目实际调整]
- 分支按任务命名，一项任务合入后从最新主分支新建下一项，不让长期分支积累无关改动。
- 提交格式：`type(scope): 中文简述`。[待确认：按项目约定调整] 不自行添加 AI 署名。

## 开工前先统一什么

1. 框架、依赖版本与锁文件。
2. 统一目录结构与能启动的基础页面。
3. 类型检查、lint、测试与构建的实际入口（见 `RUNBOOK.md` 与 CI）。
4. 本手册、开发书、AGENTS.md 等基础文档。
5. 最小共享数据结构、接口输入输出与错误格式。
6. 一份明确标识为测试数据的样例。

不需要在这一阶段设计完全部数据库字段和未来功能；先让当前任务依赖的部分清楚可用。

## 工作流程

1. 同步主分支最新状态。
2. 为本次任务建分支。
3. 在范围内开发并运行相关检查。
4. 逐个暂存本任务文件（`git add -- <具体路径>`，不用 `git add .`）。
5. 提交并推送到任务分支。
6. 创建 PR；未就绪时用 Draft 并写清依赖。
7. 复核与检查通过后合入；下一项任务从最新主分支开始。

修改前先检查未提交改动，确认归属，保护他人已有工作。不为得到「干净状态」丢弃文件、
硬重置或把无关文件一并提交。

## PR 正文

```text
解决的问题与实际行为：
改动范围：
依赖 PR / 契约 / 配置变化：
验证命令或操作步骤及结果：
未执行项、限制与剩余工作：
需要复核的成员：
```

## 多人 / 多 agent 并行

| 资源 | 做法 |
| --- | --- |
| 工作目录 | 独立 clone 或 worktree，不在同一 checkout 并发切分支、改文件或暂存 |
| 依赖 | 各自安装，锁定同一版本与锁文件；不复制 `node_modules` / `.next` / 虚拟环境 |
| 数据库 | 各自开发库与测试库；测试账号无他人或生产库写权限 |
| 上传 / 临时目录 | 各自 checkout 内被忽略的目录 |
| 端口 | 先检查占用，各用各的；不结束别人的服务 |
| 共享文件 | 契约、迁移、锁文件、根配置由一位明确作者修改，先说明用途与影响 |

启动子代理前取得用户授权，明确任务边界、允许写入的文件与验收标准。本项目当前为中档文档集，未建交接任务单文件；交接约定见 `docs/TEAM_PLAN.md`。

## 复核

- 关键变更（权限、发布、迁移、数据一致性）落实复核人或单人自查方式，作为交付门禁。
- 参与实现者的检查不记作独立复核；AI 辅助检查不记作另一位人工复核者。
- 复核未完成、验证失败或未执行、存在未解决阻塞时，不得作为可合入或可部署版本交付。

## 环境出问题时

1. 记录分支、提交、系统、工具链版本。
2. 核对锁文件与依赖是否一致，不删锁文件试运气。
3. 核对必填配置、端口、数据库与上传目录。
4. 保留实际错误，由负责人在独立目录复现，不关闭检查掩盖失败。
