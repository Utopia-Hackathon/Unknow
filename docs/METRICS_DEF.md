# 经营指标口径定义

版本：v1.0（2026-11-26）｜裁决：D010（关闭 Q003）｜上游：`docs/PAIN_POINT.md`
用途：F03 指标看板的**唯一计算依据**，也是 D-02 的实现契约。口径冲突时以本文件为准。

---

## 0. 唯一主指标声明

本项目**只用一个主指标**：**顾客流失率（`lossRate`）**。

规程原文要求「用一个经营指标对比改造前后」，因此：

- `lossRate` 是主指标，出现在演示首屏与答辩结论句里；
- 第 5 节的指标**只作辅助展示**，不得在任何文档或演示中被称作「主指标」，也不得取代 `lossRate` 作为结论依据。

选它的理由：E17 是本项目唯一有现场观察支撑的可量化事实（"约一半顾客问完等待时长后离开"），且与痛点同源——痛点说"人走了"，指标就数"人走了"。

---

## 1. 定义（分子 / 分母）

$$
\text{lossRate} = \frac{L}{S + L}
$$

| 符号 | 含义 | 取数口径 |
| --- | --- | --- |
| `L` | **流失人数**：已取号、在窗口内未入座即离开的顾客数 | `type = 'lost'` 事件，**按 `personId` 去重**（同一人撤号重取只计一次） |
| `S` | **入座人数**：已取号且在窗口内落座的顾客数 | `type = 'seated'` 事件，按 `personId` 去重 |
| 分母 | **已产生结局的顾客数** | `S + L`，即"结果已知"的人 |

### 1.1 为什么分母不用「取号总数」

如果写成 `L / 取号总数`，窗口结束时**还在排队的人**会被算进分母却永远不会出现在分子里，导致流失率被系统性低估（越靠近窗口末端越严重）。这在统计上叫右删失（right censoring）。演示时评委只要问一句"最后一分钟取号的人算进去了吗"，用错误口径就当场站不住。

### 1.2 右删失的处理（必须显式做）

- **剔除**：窗口结束时仍在排队（已 `queued` 未 `seated` 未 `lost`）的顾客，**不进分子、不进分母**；
- **单独报出**：返回 `censored = n`，并在指标页显示「另有 n 人仍在排队，未计入」。
- **禁止**：把删失者当作"留下来就餐"（会虚高效果）或当作"流失"（会虚构痛点）。

---

## 2. 统计窗口

| 项 | 规定 |
| --- | --- |
| 窗口长度 | **120 分钟**（等效午餐高峰 11:30–13:30） |
| 起算点 | 模拟开始时刻（或现场观察开始时刻） |
| 关闭规则 | 窗口结束即冻结统计，**不"补跑到底"**；末尾删失者按 1.2 处理 |

窗口必须在指标页上写出来。不同窗口长度的 `lossRate` 不可直接比较。

---

## 3. 样本量门槛

**`n = S + L` 是样本量，必须与指标一起显示。**

| 条件 | 返回 |
| --- | --- |
| `n ≥ 30` | `{ value: lossRate, sampleSize: n, ... }` 正常出数 |
| `n < 30` | `{ value: null, reason: '样本不足（n=…，需 ≥30）', sampleSize: n }` |

**禁止**在样本不足时返回 `0`、`—` 以外的任何伪数值，也禁止把 n=5 的结果写进答辩结论。这是 F03 异常流程的硬要求（"数据不足以计算时显示样本不足，不显示 0 冒充结果"）。

> 30 这个门槛是**展示用的最低要求，不是统计显著性门槛**。若要在答辩中说"差异显著"，需另做检验（本项目不做，故答辩措辞限定为"在这组模拟参数下"）。

---

## 4. 改造前后怎么对比（基线口径）

采用**配对比较（paired）**，不是拿两段随机数据比：

| 项 | 规定 |
| --- | --- |
| 随机种子 | `before` 与 `after` **同一 `seed`**，到达序列完全相同 |
| 桌位配置 | 相同（桌数、桌型分布） |
| 唯一变量 | `before` = 纯先来后到（FIFO，无桌型匹配、无回捞）；`after` = 桌型匹配 + 过号回捞 |
| 输出 | `{ before, after, delta, relDelta }` |

- `delta = after − before`（绝对差，百分点）
- `relDelta = delta / before`（相对变化；**`before = 0` 时报 `null`**，不许除零，也不许写"降低 100%"）
- 若同时改多个参数（如加桌 + 匹配），必须**分开报**，不得合并成一个"综合提升"，否则说不清是哪一项起了作用。

## 5. 辅助指标（只展示，不参与结论）

| 指标 | 公式 | 用途 |
| --- | --- | --- |
| 过号率 `skipOutRate` | `skipped` 事件数 / `called` 事件数 | 对应 E13，说明断点二严重程度 |
| 平均等位时长 `avgWait` | `mean(seatedAt − queuedAt)`，仅统计已入座者 | 支撑"还要等多久"这条痛点 |
| 桌位空置占比 `idleTableRatio` | 空置桌·分钟 / （总桌数 × 窗口分钟） | 量化"桌在等人"的浪费 |
| 回捞成功率 `reflowSuccess` | （`reflowed` 后 `seated` 人数）/ `reflowed` 事件数 | 评价 F02-02 是否真的有用 |
| 删失人数 `censored` | 见 1.2 | 数据质量，**必须显示** |

## 6. 给 D 的实现契约（对齐 `docs/CONTRACTS.md` §三）

```js
world.getMetrics(windowMinutes = 120) => {
  lossRate: number | null,
  sampleSize: number,            // = seated + lost（去重后）
  censored: number,              // 窗口末仍在排队人数
  reason: string | null,         // 样本不足时给原因
  aux: { skipOutRate, avgWait, idleTableRatio, reflowSuccess },
  window: { start, minutes },
  detail: { queued, called, seated, lost, skipped, reflowed, dedupRemoved }
}
```

实现要点：

1. **去重必须做**：同一 `personId` 多次 `queued`（撤号重取）只计首次；否则分母虚高。
2. `detail` 里的原始计数**全部保留**，指标页可展开核对——这是"不美化原始口径"的落地方式。
3. 计算是**纯函数式**的：同样的 `world` 状态与 `windowMinutes` 必须得到同样的结果，便于单测。
4. `applyScenario` 返回前后对比时，`before` / `after` 都走同一套 `getMetrics`，不许另写一份逻辑。

## 7. 展示要求（F03 硬要求）

指标页上必须同时出现三样，缺一即不合格：

1. **一行公式**：`流失率 = 流失人数 ÷ (入座人数 + 流失人数)`
2. **`n` 值**：「样本 n=…，其中另有 … 人仍在排队（未计入）」
3. **模拟数据标识**：「合成演示数据，非真实经营数据」

禁止的说法：

- ❌「效率提升 200%」（无基数、无口径）
- ❌ 把辅助指标说成主指标
- ❌ 只给一个百分数而不给 n（n=8 的 62.5% 和 n=400 的 62.5% 不是一回事）
- ❌ 把模拟结果表述为"为正弘城降低了流失率"——只能说"在这组模拟参数下"

---

## 8. 限制与失效条件

| 限制 | 后果 | 处理 |
| --- | --- | --- |
| 单点（正弘城）、单日（工作日中午）、无计数工具 | 不可外推到其他商场或周末 | 结论句限定"在这组模拟参数下" |
| 全部为模拟数据 | 不能宣称真实经营收益 | 指标页与答辩均标注模拟 |
| E17「约一半」为估计 | 不能当精确基线 | 仅校验模拟基线量级（见 §9） |
| 未取得商户访谈授权（E14） | 无真实桌位/翻台数据 | 桌型配置标注为"假设配置" |

---

## 9. 与 E17 的关系（防"调参凑数"）

E17 的「约一半」用来做**量级校验**，不用于校准：

- 模拟基线（FIFO、无回捞）的 `lossRate` 若落在 **30%–70%** 区间，视为量级合理；
- 若偏离一个数量级（如 5% 或 95%），**先检查模型参数（到达率、桌型分布、耐心时长）是否失真**；
- **严禁**为了让模拟结果"像 50%"而反向调参——那是拿结论造数据，与真实性声明冲突。

若最终未做 F02/F03（范围变更），本文件随 F03 一并延期，**不得只交指标页而不交引擎**。

## 附：算例（供 D 单测参照）

120 分钟窗口内：取号 60 人，其中入座 41 人、流失 19 人，窗口末仍有 0 人在排队。

- `n = 41 + 19 = 60`，`lossRate = 19 / 60 ≈ 0.317`（31.7%）
- 若末尾另有 6 人仍在排队未产生结局：`censored = 6`，`n` 仍为 60，**不改分母**；页面上显示"另有 6 人仍在排队，未计入"
- `before = 0.317`、`after = 0.245` → `delta = −0.072`（−7.2 个百分点），`relDelta ≈ −0.227`（相对降 22.7%）

措辞：「在这组模拟参数下，流失率由 31.7% 降至 24.5%，下降 7.2 个百分点（n=60）。」
