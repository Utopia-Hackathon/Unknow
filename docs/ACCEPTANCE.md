本文不维护：验收定义（见 `PROJECT_PLAN.md` §6）、范围表、进度概括（见 `STATUS.md`）。

> **状态**：未实现 / 通过 / 失败 / 未执行 / 受环境阻塞。五档，不许写「基本可用」。
> **「通过」必须注明实际验证层级**：单元 / 实库 / HTTP / 浏览器 / 实际手机 / 生产。
> 部分 API 或单元测试通过不等于完整页面、真实手机和生产部署通过；「未执行」也不代表没有实现。
> 局部通过不代表整体完成。测试素材注明为合成或明确标识的演示内容。

> **v0.2 口径**：依据远程 main `b40aa8f` 与 PR #31/#32/#33/#34/#35 实测状态整合。
> 表格中的「通过（单人自查）」是实施者 C 的浏览器自测，**按本文 §5 不记作 A 侧独立复核**；A 按 §6 重跑后再确认或改判。
> CI 三 job 全绿只证明构建没坏，**不等于验收通过**。

## 1. 什么时候跑哪些行

| 触发条件 | 跑哪些行 |
| --- | --- |
| 局部逻辑、页面或样式改动 | 只跑受影响的不变量与关联流程 |
| 工程初始化 | 建立类型检查、lint、业务测试与构建的实际入口，并接入 CI |
| 首次完整上线，或影响多个核心流程 | 全表适用行 + 桌面 + 实际设备 |
| 实际部署 | 生产构建、依赖、持久化、重启后可读等部署专用检查 |

## 5. 复核与报告

- 参与实现者的检查不记作独立复核；AI 辅助检查不记作另一位人工复核者。
- 仅一人可参与时记为「单人自查」，写明实现者、验证证据与未解决项。
- 已通过 / 失败 / 未执行 / 受环境阻塞分别报告。没有运行不能称已验证，没有部署不能称已上线。
- 不通过跳过断言、关闭检查、扩大容差或替换为假数据使结果通过。
