### 2.1 A12（AI 建议）判据明细

规程必做内容第（4）项原文：「决策闭环：支持假设推演并**给出人工智能建议**，用一个经营指标对比改造前后」。本项空着直接挂 25 分那一档。五条判据从 #52 的实跑里长出来，逐条可判定：

| 编号 | 判据 | 判定方式 |
| --- | --- | --- |
| A12-1 | 卡片可见且明写「规则引擎」，不得写成「AI 预测」「智能算法」 | 探针读 `.dash-rule-tag` |
| A12-2 | caveat 常显「基于模拟数据，非真实经营数据」 | 探针读 `.dash-rule-tag` / 页面文本 |
| A12-3 | 每条 `actions[]` 的 `basis` 数字能在 `evidence` 里找到同一个值 | 单测 + 人工抽核 |
| A12-4 | 改推演滑块后 headline 或 actions 变化（闭环可视） | 探针改 `#dash-add` 后比对 `.dash-delta` / headline |
| A12-5 | **指标缺键时不产出数字**：`aux` 缺 `idleTableRatio`/`reflowSuccess` 时，不得输出 100%/0%，依赖它的规则不得触发 | `src/advisor.test.mjs` 三条新单测 |

**A12-5 是权重最高的一条。** 它把「不许编数字」从口头纪律变成可执行断言。#52 当前实测触发这条 FAIL：缺 `aux` 时输出「空桌率 100%，引流动线有问题」，而这个 100% 是 `1 - (aux.seatUtilization ?? 0)` 算出来的假值。演示时评委顺着 `basis` 追问数据来源会答不上来，性质与「246 张无实拍」同类。

- A10 为 D008 新增项。**判外观只判「可辨识」不判「精细」**；但位置与信息两项按硬标准判，不合格即不通过（不因外观达标而豁免）。
- A11 为 D011 新增项。判的是**范围边界是否表达清楚**，不是楼层数量多少：`1–5F` 不开放进入属**合规做法**，但楼层选择器里出现点进去是空的按钮、或外部视角只见三层悬浮体块，均判不通过。**外壳以 D013 为准**：朝相机 +x/+z 两面剖切是合规实现，不再要求「完整（未剖切）外壳」。
- A07 判定按 **D010** 与 `docs/METRICS_DEF.md`：指标页须同时出现「公式 + n 值 + 删失人数 + 模拟数据标识」；`n<30` 显示「样本不足」。**出现 0 或任何未经样本量支撑的百分数即不通过。**
- A04–A06 的跳号/回捞/流失事件，`reason` 字段为空即不通过（F02-01 要求解释原因，无字段只能编）。

**注 1（F01-01 帧率判据，仍未判）**：PR #30 已合入 main（`cf86532`），帧率采样与三档降级链路存在；但 A 的复核机无 GPU（SwiftShader 软渲染），1440×900 的 ≥30fps 判据**判不了**，本版不判。Issue #19 保持 open，待 12-01 在有 GPU 的机器上复测后再判，**不得用 CI 绿或本次复核代替帧率通过**。
