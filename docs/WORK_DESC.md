作品名称：【待队长填写；建议「一起飞往乌托邦 · 正弘城排队决策推演」】

## 一句话

**把正弘城 6–8F 餐饮楼层做成可浏览的 3D 导览场景，用合成的排队数据驱动桌位决策推演，并以「顾客流失率」一个经营指标对比改造前后。**

## 解决什么痛点（规程必做内容第 1 项）

2026-11-24 工作日午餐高峰的现场观察（E11、E12、E13、E17）：热门店门外排队 20+ 人；出现桌型不匹配导致的跳号；叫号时顾客不在场使流程阻塞；面对约 20 人队列，**约一半顾客在问询等待时长后离开**。

商户侧看不到「这一走有多少人、为什么走」，顾客侧不知道等多久才值得等。本作品用 1–5F 不做内部、建筑外壳保留的 6–8F 场景，把这两侧放进同一个可推演的空间。依据与证据强度见 `docs/PAIN_POINT.md`。

## 做了什么

| 模块 | 内容 | 依据 |
| --- | --- | --- |
| **F01 三维导览** | 6–8F 门脸体块 + 文字招牌（贴图映射表当前合法留空）+ 程序化幕墙建筑外壳；搜索高亮、导览路径、点击门店跳到门口；总览 / 第一人称双视角 | D007、D008、D011、D012、D013 |
| **F02 排队决策闭环** | 合成排队数据驱动桌型匹配、跳号解释、过号回捞、流失记录；每条事件带 `reason` 字段 | Issue #13，`METRICS_DEF.md` |
| **F03 指标看板** | 主指标「顾客流失率」= 流失人数 /（入座人数 + 流失人数），右删失显式处理，`n<30` 判样本不足；改造前后对比 | D010、Issue #14 |
| **数据真实性** | 点位 8–10 个，来源按 `observed / public / unverified` 分级；无来源的店搜到时显示「数据待补」，不虚构点位 | D011、D012、A03 |

## 怎么用

1. 按 `docs/RUNBOOK.md` 启动本地静态服务，浏览器打开首页。
2. 楼层选择器切 6F / 7F / 8F → 旋转缩放看外观 → 搜索店名 → 跟随导览路径 → 切换第一人称漫游。
3. 打开决策/指标页 → 调整合成排队参数 → 看跳号解释与流失率前后对比。

> 操作可演示的功能**以 12-03 功能冻结时 `docs/ACCEPTANCE.md` A01–A11 的实测通过项为准**；未通过项不在视频与答辩中展示为已完成。

## 数据边界（必须说清）

- 排队与客流数据**全部为模拟数据**，不接入任何真实商业系统，不做真实支付，不宣称与正弘城存在合作关系。
- 门店名称、楼层、铺位号来自公开信息与现场观察，**点位坐标为示意**，非商场官方数据。
- 1–5F、B1、9F 不建内部，仅作建筑外壳；这不是遗漏，是范围边界（D011）。外壳按 D013 取实景照的配色与分带规律程序化绘制，不直接贴用第三方摄影；六张实景照保留作外观依据。
