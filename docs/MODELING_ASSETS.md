- 用途：决定楼层怎么叠、中庭洞开在哪、扶梯怎么跨。

## 建模提示

评分看「可浏览、可检索、有店铺点位 + 数据驱动场景变化」，示意级别即可，不做 1:1 精模：

- 店铺：把导览牌店名/铺位号录成数组，循环生成方块，绑定状态（绿有位/黄排队/红满）；
- 扶梯：斜面 + 等距台阶 + 扶手（可做滚动动画）；
- 电梯：透明竖井 + 沿 Y 轴移动的轿厢；
- 中庭挑空：楼层平面中间开洞（几块盒子拼成环形）。

## 实际盘查结果（2026-11-26 A 复核，85 张逐目录核过）

> 下面这四条是**逐张打开核对**得出的，与前面的「最值钱的几张」如有出入，以本节为准。

### 1. 格式：`izi/` 全部 32 张后缀是 `.png`，真实格式是 WEBP

| 目录 | 后缀 | 真实格式 | 结论 |
| --- | --- | --- | --- |
| `izi/` | .png ×32 | **WEBP ×32** | **后缀与格式不符** |
| `netease/` | .jpg ×26 | JPEG ×26 | 一致 |
| `official/` | .jpg ×6 / .png ×1 | JPEG ×6 / PNG ×1 | 一致 |
| `promo/` | .png ×14 / .jpg ×3 | PNG ×14 / JPEG ×3 | 一致 |
| `floorplans/` | .jpg ×3 | JPEG ×3 | 一致 |

浏览器按内容嗅探，`<img src="*.png">` 加载 WEBP **能正常显示**，所以当前演示不受影响。但两个隐患：① 用于 Blender 贴图或第三方工具链时可能报「not a PNG」；② 评委若查看素材目录会看到格式不符。
**处置建议（低优先）**：不急着批量改名（会牵动所有引用），等贴图阶段一起改，或干脆在文档里注明「izi 组为 WEBP，浏览器兼容」。

### 4. 没有 6–8F 平面图时的兜底做法（不虚构）

1. **主力店位置**用公开信息 + 门头照片定位（腾讯新闻已给 7–8F 等位最密、B1 与 7–8F 人流最大）；
2. **铺位排布**按 1F/2F 平面图的柱网、中庭位置、扶梯位置**等比套用**，只保证「相对位置合理」；
3. 每个点位在 JSON 里标 `verified: "unverified"`，UI 显示「示意位置，待现场核实」；
4. **不得**把兜底坐标写成实采坐标——这是当前代码里已经犯过的错（太二写成 7F 实为 8F、喜茶写成 6F 实为 1F）。
