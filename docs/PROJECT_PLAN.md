## 1. 我们要做什么

普通地图把用户导航到商场门口就不管了。我们以正弘城的三维数字孪生为底座，做**商场内 3D 导览地图**，
让顾客在楼层间找店、找路。**一期只承诺 3D 建模 + 导览（D004）**；就餐排队/桌位匹配优化（F02）
与指标看板（F03）是时间允许时再做的叠加项，其背后的问题来自团队实地调研的餐饮层排队痛点
（跳号、过号阻塞、顾客流失）。后续功能在此底座上陆续叠加（D003）。

> 赛道 A 对齐提醒（**官方口径已核实，E23**）：赛道 A 交付要求为 ①《痛点定义单》一页
> ②三维场景可浏览可检索有店铺点位（8–10 个起步）③**数据联动**（至少一条数据通道驱动场景变化）
> ④**决策闭环**（假设推演 + AI 建议 + 一个经营指标对比改造前后）⑤AI 使用说明。
> **「三维场景 + 数据联动 + 指标对比，缺一档降分」**——纯导览（仅 F01）将直接缺「数据联动」
> 与「指标对比」两档，且 ④⑤ 无着落（O05）。若维持 D004，需尽快裁决对齐方案或重议 Q004。
> **→ 2026-11-25 裁决（G04）**：维持 D004 一期纯导览，已知悉并接受缺档降分风险；
> F02/F03 待 F01 完成后另议（台账 X-01 二次裁决、O05 关闭）。
> 利好：组委会提供金水商圈基准场景（自带正弘城场景可加分，E23）；系统数据必须模拟、
> 不得宣称接入真实商业系统、不做真实支付——与 D005 的自建粗模 + 模拟数据路线天然吻合。

## 4. 功能规格（F 编号）

每块写全七项：使用者、前置条件、主流程、异常流程、业务规则、可配置边界、关联决策。
最容易漏的是**异常流程**和**可配置边界**。

### F01 商场 3D 导览地图（数字孪生底座）

- 使用者：顾客（逛店者/就餐者）
- 前置条件：已加载正弘城目标楼层（至少 6/7/8 餐饮层）3D 场景与店铺点位
- 主流程：1. 打开演示 → 2. 浏览楼层 3D 视图（缩放/旋转/切层）→ 3. 搜索或点选店铺 → 4. 显示店铺位置与楼层内导览路径
- 异常流程：模型未加载完成时给出占位与重试；店铺点位缺失时标注「数据待补」而非静默不显示；路径不可达（跨楼层）时提示改用垂直交通点
- 业务规则：店铺点位数据以 `docs/RESEARCH.md` 实地核查为准，未核实店铺标「待核实」；不虚构店铺；**店铺点位 8–10 个起步**（E23 官方要求）；场景可用组委会基准场景保底、自带正弘城场景加分（E23）
- 可配置边界：初始视角、楼层开放范围（本期 6–8 楼）、导览路径算法参数 [待确认]、导航移动方式（已定：D007——视角双模式 + 推进三层并存）
- 关联决策：D002、D003；实现方案见 D006；导航移动方式见 D007

### F02 就餐排队与桌位匹配优化（**一期必做**，D009；原 D004 的 stretch 标注已作废）

- 使用者：顾客（等位者）、商户（叫号员）
- 前置条件：F01 就餐层场景可用；店铺桌位/桌型数据可用（模拟数据须明确标识）
- 主流程：1. 顾客按人数取号 → 2. 系统给出预估等待时长 → 3. 空桌释放时按「桌型 ↔ 排队者人数」匹配叫号（而非纯先来后到）→ 4. 处理过号/暂缺（限时回捞或顺延）→ 5. 汇总指标数据
- 异常流程：叫号无人应答（E13 过号阻塞）→ 进入过号池可回捞；无可匹配桌型的排队者 → 明确提示等待原因（E12 跳号的根因是桌型不匹配，需向用户解释而非暗箱跳号）；顾客离开（E17 流失）→ 记录流失原因
- 业务规则：匹配优先级、过号宽限时间、预估等待模型的规则以 Q004 裁决为准（Q003 已由 D010 裁决）；演示用模拟数据必须标注「合成演示数据」
- 可配置边界：过号宽限秒数、桌型分类粒度、预估模型参数 [待确认]
- 关联决策：D003；范围以 Q004 裁决为准

### F03 经营指标看板（**一期必做**，D009；指标口径见 D010 与 `METRICS_DEF.md`）

- 使用者：商户/评委（演示对象）
- 前置条件：F02 产生排队事件数据
- 主流程：1. 跑一轮模拟或演示排队 → 2. 计算选定经营指标 → 3. 单屏展示指标数值与前后对比（方案启用前 vs 启用后）
- 异常流程：数据不足以计算时显示「样本不足」，不显示 0 冒充结果
- 业务规则：指标定义唯一（D010：顾客流失率），口径写在展示页上；不换算、不美化原始口径；样本量 n<30 显示「样本不足」（`METRICS_DEF.md` §3）
- 可配置边界：对比基线口径（已定：配对比较，同 seed、同到达序列，唯一变量 FIFO→桌型匹配+回捞；见 `METRICS_DEF.md` §4）
- 关联决策：D010（指标选取）、D009（一期范围）

## 6. 验收定义

> 逐项结果见 `docs/ACCEPTANCE.md`，本文件不重复维护。

每条给可判定的输入、操作与预期结果，按 F 编号分组。演示数据须标注「合成演示数据」。

- F01-01 给定 6–8 楼场景已加载 → 打开演示页 → 3D 楼层可见、可旋转缩放、可切层，帧率不低于 [待确认] fps
  - 外观精度按 **D008**：门头贴图 + 统一尺寸体块即达标，**不逐店精模**；但楼层须正确、点位不得落进中庭；无来源信息标 `verified: "unverified"` 并在 UI 提示
- F01-02 给定店铺 POI 数据 → 搜索店铺名（如「巴奴」）→ 高亮该店铺位置并生成从当前视点到该店铺的导览路径
- F01-03 给定某店铺无点位数据 → 搜索该店铺 → 显示「数据待补」标注，不静默失败
- F02-01 给定合成排队数据（含不同人数的排队者与不同桌型）→ 释放一张空桌 → 叫号选择与桌型匹配的排队者而非机械按序，且界面解释跳号原因
- F02-02 给定被叫号顾客不在场 → 触发过号流程 → 进入可回捞状态并记录过号事件
- F02-03 给定顾客了解预计等待后离开 → 记录流失事件并计入指标
- F03-01 给定一轮完整模拟数据 → 打开指标页 → 显示选定主指标数值、口径说明与启用前后对比；样本不足时显示「样本不足」

不写「体验流畅」「界面美观」「成功率合理」这类无法证伪的话；需要时转成可测指标。
